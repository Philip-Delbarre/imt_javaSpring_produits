# client-panier

API REST Spring Boot (Jakarta REST / Jersey) pour gérer des **clients** et des **produits**.
Un seul projet, deux styles d'architecture :

| Partie       | Style                                                  | Dossiers                                                    |
| ------------ | ------------------------------------------------------ | ----------------------------------------------------------- |
| **Produits** | **MVC en couches** (Controller → Service → Repository) | `controller/`, `service/`, `repository/`, `entity/`, `dto/` |
| **Clients**  | **Hexagonal** (ports & adapters)                       | `model/`, `application/`, `adapter/`                        |

Les deux parties ne sont liées que par **identifiant** : pas de clé étrangère, pas de table de liaison.

## Structure

```
Pour le produit // voici le squelete

com.merchant
├── Application                 seule classe de démarrage
├── JerseyConfig                configure l'API REST (chemin /api, classes exposées) — PAS la base de données
├── exception/                  erreurs métier + convertisseurs exception → JSON (404, 400)
│
├── controller/ProduitController     MVC : expose /api/produits
├── service/ProduitService
├── repository/ProduitRepository
├── entity/Produit                   entité JPA (table "produits")
├── dto/                      HEXAGONAL : domaine en Java pur
│   ├── ProduitRequest
│   └── ProduitResponse             ce que le client sait d'un produit
           ProduitAdapter (seul pont vers la partie MVC)
```

## Qui configure quoi ?

| Outil                                            | Rôle                                                                                 |
| ------------------------------------------------ | ------------------------------------------------------------------------------------ |
| `application.properties`                         | **connexion à la base** (URL H2, login), mode Hibernate (`ddl-auto`), console H2     |
| classes `@Entity` (`Produit`, `ClientJpaEntity`) | **structure des tables** : Hibernate les crée au démarrage                           |
| interfaces `JpaRepository`                       | **requêtes CRUD** générées par Spring Data                                           |
| `JerseyConfig`                                   | **API REST uniquement** : préfixe `/api`, classes exposées, convertisseurs d'erreurs |

Une seule base H2 (fichier `./data/panier.mv.db`), deux tables indépendantes. Équivalent SQL indicatif :

```sql
CREATE TABLE produits (
  id_produit    INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  nom_produit   VARCHAR(255) NOT NULL,
  designation   VARCHAR(255),
  prix_unitaire DECIMAL(10,2) NOT NULL
);

```

## Lancer

Prérequis : JDK 17 ou plus.

```bash
mvnw.cmd spring-boot:run        # Linux / macOS : ./mvnw spring-boot:run
```

- API : http://localhost:8080/api
- Console H2 : http://localhost:8080/h2 (JDBC URL `jdbc:h2:file:./data/panier`, user `sa`, mot de passe vide)

## Endpoints

### Produits : `/api/produits`

| Méthode | URL                  | Rôle                        |
| ------- | -------------------- | --------------------------- |
| GET     | `/api/produits`      | liste                       |
| GET     | `/api/produits/{id}` | détail (404 si inconnu)     |
| POST    | `/api/produits`      | création (201 + `Location`) |
| PUT     | `/api/produits/{id}` | modification                |
| DELETE  | `/api/produits/{id}` | suppression (204)           |

## Exemples (corps JSON)

Créer un produit (`POST /api/produits`) :

```json
{ "nomProduit": "Clavier", "designation": "Clavier mécanique AZERTY", "prixUnitaire": 59.9 }
```

## Erreurs

Corps JSON : `{ "status": 400, "message": "...", "erreurs": { "champ": "message" } }`
(`erreurs` uniquement pour les erreurs de validation).

Exemple : un `POST /api/clients` dont le JSON contient `"prenon"` au lieu de `"prenom"` renvoie

```json
{ "status": 400, "message": "Données invalides", "erreurs": { "prenom": "le prénom est obligatoire" } }
```

- `404` : client ou produit introuvable.
- `400` : champ obligatoire manquant, email invalide, prix négatif, id de produit inexistant, corps absent.

## Validation et fonctionnement hors ligne

Aucune bibliothèque de validation n'est utilisée (ni `jakarta.validation`, ni Hibernate Validator) :
les contrôles sont écrits à la main dans `CreationClientDTO.verifier()` et `ProduitRequest.verifier()`.
Le `pom.xml` ne contient que les dépendances d'origine (JPA, Jersey, Web, H2, Test) : si elles sont dans
ton cache Maven (`~/.m2`), le projet se compile sans accès à Maven Central.
